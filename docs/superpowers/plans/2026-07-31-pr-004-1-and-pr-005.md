# PR-004.1 Acceptance Persistence and PR-005 Preliminary Matching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Persist reviewer acceptance safely, then create deterministic, auditable preliminary CV-to-role matching using only accepted evidence and active role profiles.

**Architecture:** PR-004.1 replaces the runtime in-memory extraction adapter with a SQLAlchemy repository and adds immutable acceptance/revision semantics. PR-005 adds a pure rule engine plus persistence/API adapters; its service owns input-eligibility and anti-double-counting guards, so no caller can bypass them.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy async 2.x, Alembic, PostgreSQL development stack, pytest/pytest-asyncio, Ruff and mypy.

## Global Constraints

- Keep the FastAPI modular monolith; do not add a microservice, queue broker, external AI provider or LMS feature.
- CV/JD remain fixture-backed untrusted data. Never persist/log raw documents, raw prompts, raw model output, PII values or credentials.
- Model work remains outside request handling and through ModelGateway; PR-005 performs no model call.
- Official matching accepts only CV extraction profile ACCEPTED, accepted JD source and Role Competency Profile ACTIVE.
- No verified competency, automatic hire/reject decision or sole overall score. Every preliminary match and criterion requires human review.
- Public development APIs use ADR-0007 actor headers and safe error envelope; actor ID never comes from JSON.
- Audit writes are append-only and transactionally required for acceptance/match completion.
